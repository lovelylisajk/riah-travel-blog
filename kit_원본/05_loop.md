# 05. 한 바퀴 도는 순서 — 문제를 AI가 확인하고 고친 뒤 다시 검사하게

> 검사기가 *"3행에 목록 기호가 있다"* 라고 잡아줘도, **내가 매번 "그럼 이렇게 고쳐"라고 알려줘야** 다음이 굴러갔습니다.
> 그 알려주는 일을 AI 쪽으로 옮기는 순서입니다.

## 한 바퀴

```text
① 글을 쓴다                                   (모델 1회)
     │
     ▼
② 검사한다 ─── 걸린 것 목록
     │
     ▼
③ AI가 걸린 것을 스스로 나눈다
     │   A 규칙으로 끝  ·  B 다시 써야 함  ·  C 사람만  (04번 파일 참조)
     │
     ├── C가 하나라도 있으면 ─────────────▶ 멈춘다. 사람에게 넘긴다
     │
     ├── B가 있으면 ──▶ ④ AI에게 그것만 콕 집어 다시 시킨다  (모델 1회, 딱 한 번)
     │                        │
     │                        ▼
     │                   ⑤ 다시 검사한다
     │                        │
     └── A만 남으면 ──▶ ⑥ 정해진 규칙으로 교정한다          (모델 0회)
                              │
                              ▼
                         ⑦ 다시 검사한다
                              │
                              ▼
                         ⑧ 걸린 것 0건 ──▶ 사람 승인 대기   ← 여기는 사람
```

## 각 칸에서 지킬 것

| 칸 | 지킬 것 |
|---|---|
| ③ 나누기 | **못 고칠 게 섞였으면 아예 손대지 않습니다.** 반만 고치면 "고쳤다"는 착각만 남습니다 |
| ④ 다시 시키기 | **한 편에 딱 한 번.** 두 번째 요청은 새 문제를 만들 확률이 올라갑니다 |
| ④ 다시 시키기 | 지시에 **"원래 목소리·제목·주소·숫자는 그대로 두라"** 를 항상 넣습니다 |
| ⑤⑦ 다시 검사 | **처음과 똑같은 검사**를 씁니다. 검사를 느슨하게 바꿔서 통과시키면 안 됩니다 |
| ⑥ 규칙 교정 | 04번 파일의 좁은 목록만. 애매하면 안 고칩니다 |
| ⑧ 통과 | **검사 통과 ≠ 발행해도 된다.** 사실 확인·이미지·최종 승인은 여기 뒤입니다 |

## 자주 하는 착각

| 이건 루프가 아닙니다 | 이게 루프입니다 |
|---|---|
| 검사 결과를 파일에 쌓아둔다 | AI가 그 결과를 읽고 **뭘 고칠지 스스로 정한다** |
| 내가 보고 "이거 고쳐"라고 말한다 | AI가 **고칠 목록을 스스로 만들어 온다** |
| 매번 똑같은 지시로 다시 시킨다 | **이번에 걸린 것만** 콕 집은 지시를 새로 만든다 |
| 고친 기록이 내 머릿속에만 있다 | 고친 기록이 **다음 실행의 입력**으로 들어간다 |

## 실패를 성공으로 만들지 않기

여기가 제일 조심할 자리입니다.

- 고치다 실패하면 **원본을 그대로 두고 「실패」로 남깁니다.** 반쯤 고친 걸 통과로 바꾸지 않습니다
- 교정 뒤에 **숫자·주소·제목이 그대로인지 다시 셉니다.** 하나라도 달라졌으면 교정본을 버립니다
- **자동으로 발행 승인까지 가지 않게** 막아둡니다. 마지막 문은 사람이 엽니다

## 다음 글로 넘기는 루프 (한 단계 위)

위는 **글 한 편**을 고치는 것입니다. 그 글이 끝나면 배운 게 사라집니다.
다음 글에 넘기려면 한 겹이 더 필요합니다.

```text
발행된 글 ──▶ 내 초안과 실제로 나간 글을 대조한다 (기계)
                  │
                  ▼
            달라진 데를 AI가 읽고 ──▶ "이 사람은 이렇게 고치더라" 규칙안을 낸다
                  │
                  ▼
            안전 검사 ──┬─ 통과 ──▶ 규칙 칸에 넣는다 ──▶ 다음 글쓰기가 이걸 읽는다
                        │
                        └─ 걸림 ──▶ 기존 규칙 그대로 두고 「실패」로 기록
```

**안전 검사에 꼭 넣을 것** — 이런 규칙안은 받으면 안 됩니다.

- `[ ]` 없는 경험·일화를 **지어내라**는 것
- `[ ]` 근거·출처를 **지우라**는 것
- `[ ]` 표·자료를 **통째로 빼라**는 것
- `[ ]` `[ 내 분야에서 절대 하면 안 되는 것 ]`

> 실제로 이 검사에 걸려서 규칙안 10개가 통째로 거부된 적이 있습니다.
> 그중 하나가 *"겪은 일화·혼잣말은 새로 넣되"* 였습니다. 그냥 들어갔으면 **없는 경험을 지어내는 글**이 나갔을 겁니다.
> **막힌 건 고장이 아니라 안전장치가 일한 것입니다.** 다만 **막힌 뒤에 다시 시도하는 길**은 따로 만들어야 합니다.

---

## 다음 글로 넘기는 루프를 «실제로» 붙이는 법

위 그림까지는 종이로도 됩니다. 진짜 어려운 건 **배운 걸 다음 글이 실제로 읽게** 하는 것입니다.
제가 쓰는 순서는 이렇습니다.

```text
① 막힌 기록에서 «사유» 와 «걸린 줄» 만 꺼낸다        ← 글 전문을 넘기지 않는다
② AI에게 한 번 물어 «문제 · 개선안 1개 · 적용 조건» 을 받는다
③ 안전 검사에 걸리면 버린다 (아래 목록)
④ 통과한 것만 «운영 규칙과 다른 파일» 에 저장한다
⑤ 다음 글 쓰는 프로그램이 그 파일을 «직접 읽어» 지시에 붙인다
⑥ 같은 검사로 다시 재고, 안 나아졌으면 멈춘다
```

**⑤가 핵심입니다.** 사람이 복붙해야 돌아가면 아직 연결된 게 아닙니다.

### 모델이 필요한 부분과 아닌 부분

| 단계 | 모델 | 없이도 되나 |
|---|:--:|---|
| ① 기록에서 근거 꺼내기 | ✕ | 됩니다 |
| ② 개선안 만들기 | **○ 1회** | 안 됩니다 — 여기만 모델이 필요합니다 |
| ③ 안전 검사 | ✕ | 됩니다 (정해진 목록으로 거릅니다) |
| ④ 저장 | ✕ | 됩니다 |
| ⑤ 다음 글에 넣기 | **○ 1회** | 글을 새로 쓰니 필요합니다 |
| ⑥ 다시 재기 | ✕ | 됩니다 |

**한 바퀴에 모델은 딱 2번**입니다. 그 이상이면 뭔가 잘못된 겁니다.

### 가상 입력 · 출력 (모델 없이 읽어만 봐도 됩니다)

**넣는 것** — 막힌 기록에서 꺼낸 근거

```
막힌 사유
- 본문이 하한 [1,500]자에 못 미침
- [줄머리 목록 기호]가 4줄 있음

걸린 줄
43행: - [항목 하나]
44행: - [항목 둘]
```

**나오는 것** — AI가 돌려주는 개선안 (JSON 한 덩이)

```json
{
  "problem": "본문이 하한에 못 미쳤고 금지된 줄머리 목록 기호를 썼다",
  "rule": "소제목마다 근거와 조건을 문장으로 풀어 하한을 넘기고, 나열은 줄머리 기호 대신 가운뎃점으로 쓴다",
  "applies_when": "여러 항목을 나열해야 하는 글",
  "kind": "existing_rule_missed"
}
```

**저장되는 것** — 여기에 «어디서 왔는지» 와 «내용 해시» 를 같이 답니다

```json
{
  "rule_id": "imp-[16자리]",
  "source_run": "[막혔던 실행 이름]",
  "status": "accepted",
  "kind_label": "놓친 기존 규칙을 다음 작성에 반영",
  "integrity": { "version": 2,
                 "fields": ["rule_id", "source_run", "problem", "rule", "applies_when"],
                 "sha256": "[해시]" }
}
```

> **해시를 왜 다나** — 이 파일을 손으로 고쳐 몰래 다른 지시를 끼워 넣는 걸 막습니다.
> 한 글자라도 바뀌면 다음 실행이 **아예 멈춥니다.**
> 그리고 **개선안 문장만** 해시하면 안 됩니다. 「문제」와 「적용 조건」도 지시에 같이 들어가니까요.

### 받는 사람이 채울 칸

| | 우리 것 |
|---|---|
| 개선안을 저장할 폴더 (운영 규칙과 **다른** 곳) | `[ ]` |
| 한 바퀴에 허용할 모델 호출 수 | `[ 2 ]` |
| 「개선됐다」고 부를 기준 | `[ 예: 걸린 것이 줄고 «새로 생긴 것이 0» ]` |
| 안 나아졌을 때 할 일 | `[ 예: 실패로 남기고 멈춘다. 다시 안 부른다 ]` |

### ⚠️ 같은 실행을 두 번 부르지 않게

**결과 파일이 있는지만 보면 안 됩니다.** 모델이 도중에 터지면 파일이 없어서 다음번에 또 부릅니다 — 돈이 조용히 두 배가 됩니다.

**부르기 «전에» 표식을 먼저 만드세요.** 폴더 하나를 만드는 것으로 충분합니다(이미 있으면 만들기가 실패하니 그게 곧 자물쇠입니다).

| 상황 | 어떻게 되어야 하나 |
|---|---|
| 성공한 뒤 다시 실행 | 저장된 것을 돌려준다. 모델 **안** 부른다 |
| **모델이 터진 뒤** 다시 실행 | 실패 기록을 돌려준다. 모델 **안** 부른다 |
| 표식만 있고 결과가 없음 | 앞 실행이 죽은 것. 모델 **안** 부른다 |
| 동시에 두 번 들어옴 | 한쪽만 부른다 |
